## 1. Introducción

Este documento define los requerimientos iniciales del sistema para el Proyecto Final de la asignatura Desarrollo de Software VII. Establece una base clara para el diseño, desarrollo e implementación de una aplicación web dinámica en PHP, orientada a la recomendación personalizada de películas y series.

---

## 2. Objetivo del Proyecto

Desarrollar una aplicación web dinámica en PHP que actúe como una **Plataforma de Recomendación de Películas/Series**. El sistema permitirá a los usuarios registrarse, iniciar sesión, explorar contenido audiovisual y recibir recomendaciones personalizadas según sus intereses, aplicando cookies, sesiones y webservices con XML/JSON.

---

## 3. Alcance

### Incluye:

- Registro e inicio de sesión de usuarios con roles (estándar y administrador)
- Manejo de sesiones para autenticación y cookies para personalización
- Base de datos relacional con usuarios, contenido, géneros y preferencias
- Formulario de preferencias con selección de géneros favoritos
- Motor de recomendaciones basado en géneros e historial de navegación
- Panel de administración para gestión de contenido y estadísticas de uso
- Consumo e intercambio de datos mediante archivos XML y JSON
- Validación y sanitización de formularios contra XSS, SQLi y fuerza bruta
- Interfaz amigable con tema claro/oscuro mediante cookies

### No incluye:

- Reproducción de contenido multimedia (streaming)
- Integración con plataformas externas de pago
- Sistema de mensajería o chat entre usuarios
- Aplicación móvil nativa

## 7. Reglas de Negocio

- Solo los usuarios con sesión activa pueden ver recomendaciones personalizadas.
- Las recomendaciones se basan únicamente en los géneros seleccionados por el usuario y/o su historial de navegación.
- Solo el rol de administrador puede agregar, editar o eliminar contenido del catálogo.
- Las contraseñas deben almacenarse de forma segura (hash) en la base de datos.
- Un usuario no puede tener más de un registro con el mismo correo electrónico.
- Las cookies de personalización deben tener una vigencia definida (por ejemplo, 30 días).

---

## 8. Supuestos

- El entorno de desarrollo y pruebas dispondrá de un servidor local con PHP 8.x y MySQL.
- Los integrantes del grupo tienen acceso a internet para consulta de recursos durante el desarrollo.
- Se contará con datos de prueba (películas/series) precargados en la base de datos para la presentación.
- Los archivos XML y JSON se gestionarán localmente dentro del proyecto.

---

## 9. Restricciones

- El proyecto debe desarrollarse exclusivamente en **PHP** como lenguaje del lado del servidor.
- El tiempo de desarrollo está limitado al período académico del curso.
- No se puede usar ningún framework PHP (como Laravel o Symfony); el desarrollo debe ser en PHP puro.
- El grupo de trabajo está compuesto por exactamente 2 integrantes.
- La presentación tiene una duración máxima definida por el docente; las pruebas del grupo evaluador no pueden superar **20 minutos**.

## 10. Riesgos

| Riesgo                                                               | Impacto | Mitigación                                                                                      |
| -------------------------------------------------------------------- | ------- | ----------------------------------------------------------------------------------------------- |
| Vulnerabilidades de seguridad no corregidas antes de la presentación | Alto    | Realizar pruebas de seguridad (XSS, SQLi) con antelación y aplicar sanitización desde el inicio |
| Fallas en la base de datos durante la demo                           | Alto    | Mantener un backup de la BD y un script de restauración rápida                                  |
| Lógica de recomendaciones incompleta o imprecisa                     | Medio   | Probar el sistema con distintos perfiles de usuario y géneros antes de la presentación          |
| Tiempo insuficiente para implementar todas las funcionalidades       | Medio   | Priorizar los requerimientos de alta prioridad y dejar los de baja para el final                |
| El equipo evaluador encuentra fallas críticas en las pruebas         | Alto    | Preparar casos de prueba propios con anticipación y corregir fallas identificadas internamente  |

---

## 11. Criterios de Aceptación

- El sistema permite registrar usuarios, iniciar sesión y cerrar sesión correctamente.
- Las sesiones persisten durante la navegación y se destruyen al cerrar sesión.
- Las cookies almacenan y recuperan correctamente las preferencias del usuario.
- El sistema de recomendaciones muestra contenido coherente con los géneros preferidos del usuario.
- El administrador puede agregar, editar y eliminar películas/series sin errores.
- La aplicación consume correctamente al menos un archivo XML y uno JSON.
- Los formularios rechazan entradas maliciosas (XSS, SQLi) sin romper el flujo de la aplicación.
- La interfaz es navegable, organizada y visualmente diferenciada entre usuarios estándar y administrador.
- La aplicación responde correctamente a las pruebas realizadas por el grupo evaluador durante la presentación.
